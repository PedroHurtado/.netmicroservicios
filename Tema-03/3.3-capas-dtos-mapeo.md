## ¿Por qué DTOs?

**DTO** (*Data Transfer Object*) es un patrón que encapsula datos para transferencia entre capas o servicios.

### El problema sin DTOs

```csharp
// Endpoint recibe y devuelve la entidad de dominio directamente
[HttpPost]
public async Task<IActionResult> Create([FromBody] Product product)
{
    // ⚠️ Problema 1: Expones la entidad de dominio
    // ⚠️ Problema 2: El cliente puede modificar campos que no debería (ej: createdAt)
    // ⚠️ Problema 3: Cambios en Product rompen clientes
    await _repository.AddAsync(product);
    return CreatedAtAction(nameof(Create), new { id = product.Id }, product);
}
```

### Ventajas de los DTOs

1. **Contrato explícito:** El cliente sabe exactamente qué campos puede enviar/recibir
2. **Flexibilidad:** Cambios en la entidad no afectan clientes
3. **Seguridad:** No expongas campos sensibles (ej: `internalCost`, `margin`)
4. **Validación específica:** DTOs pueden tener validaciones diferentes que la entidad
5. **Performance:** Selecciona solo los campos necesarios para cada operación

## Tipos de DTOs

### 1. CreateProductRequest (DTO de entrada)

```csharp
namespace Catalog.API.Features.Products.Dtos;

public record CreateProductRequest(
    string Name,
    string Description,
    decimal Price,
    int Stock
);
```

**Usar en:** El Endpoint recibe este DTO, lo transforma en Command de dominio.

### 2. UpdateProductRequest

```csharp
public record UpdateProductRequest(
    string Name,
    string Description,
    decimal Price,
    int Stock
);
```

### 3. ProductResponse (DTO de salida)

```csharp
public record ProductResponse(
    Guid Id,
    string Name,
    string Description,
    decimal Price,
    int Stock,
    DateTime CreatedAt,
    DateTime? UpdatedAt
);
```

**Usar en:** El Handler devuelve este DTO para exponerlo al cliente.

### 4. ProductListItemResponse (DTO de listado optimizado)

```csharp
public record ProductListItemResponse(
    Guid Id,
    string Name,
    decimal Price,
    int Stock
);
```

**Ventaja:** En un listado, no necesitamos toda la información, reducimos payload.

## Mapeo entre capas

El mapeo transforma datos entre DTOs, Commands y entidades de dominio.

### Opción 1: Mapeo manual

```csharp
// En el Endpoint
var command = new CreateProductCommand(
    request.Name,
    request.Description,
    request.Price,
    request.Stock
);

var response = await _mediator.Send(command);

// En el Handler
var product = Product.Create(
    Guid.NewGuid(),
    command.Name,
    command.Description,
    command.Price,
    command.Stock
);
await _repository.AddAsync(product);

return new ProductResponse(
    product.Id,
    product.Name,
    product.Description,
    product.Price,
    product.Stock,
    product.CreatedAt,
    product.UpdatedAt
);
```

**Ventaja:** Explícito, sin dependencias externas.  
**Desventaja:** Repetitivo y propenso a errores.

### Opción 2: Usar AutoMapper (recomendado para proyectos grandes)

**Instalar:**

```bash
dotnet add package AutoMapper
dotnet add package AutoMapper.Extensions.Microsoft.DependencyInjection
```

**Configurar MappingProfile:**

```csharp
namespace Catalog.API.Infrastructure.Mapping;

using AutoMapper;
using Catalog.API.Features.Products.Create;
using Catalog.API.Features.Products.Domain;
using Catalog.API.Features.Products.Dtos;

public class ProductMappingProfile : Profile
{
    public ProductMappingProfile()
    {
        // Request -> Command
        CreateMap<CreateProductRequest, CreateProduct.Command>();

        // Product entity -> Response
        CreateMap<Product, ProductResponse>();

        // Product entity -> ListItem Response
        CreateMap<Product, ProductListItemResponse>();
    }
}
```

**Registrar en Program.cs:**

```csharp
builder.Services.AddAutoMapper(typeof(Program));
```

**Usar en Endpoint:**

```csharp
[HttpPost]
public async Task<IActionResult> Create([FromBody] CreateProductRequest request)
{
    var command = _mapper.Map<CreateProduct.Command>(request);
    var response = await _mediator.Send(command);
    return CreatedAtAction(nameof(Create), new { id = response.Id }, response);
}
```

### Opción 3: Mappers específicos (pattern matching)

```csharp
namespace Catalog.API.Features.Products.Mappers;

using Catalog.API.Features.Products.Create;
using Catalog.API.Features.Products.Domain;
using Catalog.API.Features.Products.Dtos;

public static class ProductMappers
{
    public static CreateProduct.Command ToCommand(this CreateProductRequest request) =>
        new CreateProduct.Command(request.Name, request.Description, request.Price, request.Stock);

    public static ProductResponse ToResponse(this Product product) =>
        new ProductResponse(
            product.Id,
            product.Name,
            product.Description,
            product.Price,
            product.Stock,
            product.CreatedAt,
            product.UpdatedAt
        );

    public static ProductListItemResponse ToListItem(this Product product) =>
        new ProductListItemResponse(product.Id, product.Name, product.Price, product.Stock);
}
```

**Usar:**

```csharp
var command = request.ToCommand();
var response = product.ToResponse();
```

**Ventaja:** Lightweight, sin reflexión.  
**Desventaja:** Requiere mantenimiento manual.

## Ejemplo completo: GetProductById

### GetProductByIdQuery.cs

```csharp
namespace Catalog.API.Features.Products.GetById;

using MediatR;

public record GetProductByIdQuery(Guid Id) : IRequest<GetProductByIdResponse>;
```

### GetProductByIdHandler.cs

```csharp
namespace Catalog.API.Features.Products.GetById;

using MediatR;
using Catalog.API.Features.Products.Domain;
using Catalog.API.Features.Products.Dtos;
using Catalog.API.Features.Products.Mappers;

public class GetProductByIdHandler : IRequestHandler<GetProductByIdQuery, GetProductByIdResponse>
{
    private readonly IProductRepository _repository;

    public GetProductByIdHandler(IProductRepository repository)
    {
        _repository = repository;
    }

    public async Task<GetProductByIdResponse> Handle(GetProductByIdQuery request, CancellationToken cancellationToken)
    {
        var product = await _repository.GetByIdAsync(request.Id, cancellationToken);

        if (product is null)
            throw new ProductNotFoundException(request.Id);

        return new GetProductByIdResponse(
            product.Id,
            product.Name,
            product.Description,
            product.Price,
            product.Stock,
            product.CreatedAt,
            product.UpdatedAt
        );
    }
}
```

### GetProductByIdEndpoint.cs

```csharp
namespace Catalog.API.Features.Products.GetById;

using MediatR;
using Microsoft.AspNetCore.Mvc;

[ApiController]
[Route("api/v1/products")]
public class GetProductByIdEndpoint : ControllerBase
{
    private readonly IMediator _mediator;

    public GetProductByIdEndpoint(IMediator mediator)
    {
        _mediator = mediator;
    }

    [HttpGet("{id:guid}")]
    [ProduceResponseType(typeof(GetProductByIdResponse), StatusCodes.Status200OK)]
    [ProduceResponseType(StatusCodes.Status404NotFound)]
    public async Task<IActionResult> GetById([FromRoute] Guid id)
    {
        var response = await _mediator.Send(new GetProductByIdQuery(id));
        return Ok(response);
    }
}

public record GetProductByIdResponse(
    Guid Id,
    string Name,
    string Description,
    decimal Price,
    int Stock,
    DateTime CreatedAt,
    DateTime? UpdatedAt
);
```

## Manejo global de excepciones

```csharp
namespace Catalog.API.Infrastructure.Middleware;

using Microsoft.AspNetCore.Mvc;
using Catalog.API.Features.Products.Domain;

public class GlobalExceptionMiddleware
{
    private readonly RequestDelegate _next;
    private readonly ILogger<GlobalExceptionMiddleware> _logger;

    public GlobalExceptionMiddleware(RequestDelegate next, ILogger<GlobalExceptionMiddleware> logger)
    {
        _next = next;
        _logger = logger;
    }

    public async Task InvokeAsync(HttpContext context)
    {
        try
        {
            await _next(context);
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "Unhandled exception occurred");
            await HandleExceptionAsync(context, ex);
        }
    }

    private static Task HandleExceptionAsync(HttpContext context, Exception exception)
    {
        context.Response.ContentType = "application/json";

        var response = new ProblemDetails();

        switch (exception)
        {
            case ProductNotFoundException:
                context.Response.StatusCode = StatusCodes.Status404NotFound;
                response.Status = StatusCodes.Status404NotFound;
                response.Title = "Not Found";
                response.Detail = exception.Message;
                break;

            case InvalidProductException:
                context.Response.StatusCode = StatusCodes.Status400BadRequest;
                response.Status = StatusCodes.Status400BadRequest;
                response.Title = "Bad Request";
                response.Detail = exception.Message;
                break;

            default:
                context.Response.StatusCode = StatusCodes.Status500InternalServerError;
                response.Status = StatusCodes.Status500InternalServerError;
                response.Title = "Internal Server Error";
                response.Detail = "An unexpected error occurred";
                break;
        }

        return context.Response.WriteAsJsonAsync(response);
    }
}
```

**Registrar en Program.cs:**

```csharp
app.UseMiddleware<GlobalExceptionMiddleware>();
```

## Comparativa: Mapeo manual vs AutoMapper

| Aspecto | Manual | AutoMapper |
|---------|--------|-----------|
| Setup | Ninguno | Configuración inicial |
| Performance | Más rápido (compilado) | Más lento (reflexión) |
| Mantenibilidad | Explícito | Menos código |
| Debugging | Directo | Más complejo |
| Escalabilidad | Tedioso en proyectos grandes | Excelente |
| Complejidad | Simple | Intermedia |

**Recomendación:** Para **ShopMicro** (proyecto educativo pequeño), usa **mappers específicos**. Para proyectos en producción con 20+ entidades, usa **AutoMapper**.

---

## Puntos clave

- **DTOs:** Desacopla la API del dominio, permite evolucionar independientemente
- **Request vs Response:** DTOs diferentes para entrada y salida
- **Mapeo:** Elige entre manual (simple) o AutoMapper (escalable)
- **Capas:** Organiza por responsabilidad, no por tipo técnico
- **Excepciones de dominio:** Comunica errores de negocio
- **ProblemDetails:** Estándar RFC 7807 para respuestas de error
