## ¿Qué es un Health Check?

Un **Health Check** es un endpoint que verifica si un servicio está **operativo** y listo para recibir tráfico.

### Casos de uso

✅ **Kubernetes:** Readiness/Liveness probes reinician pods fallidos  
✅ **Load Balancers:** Removimiento automático de instancias caídas  
✅ **Monitoreo:** Sistemas de alertas detectan problemas  
✅ **Orquestación:** Decisiones de escalado basadas en salud  
✅ **API Gateway:** Enrutamiento a instancias saludables  

---

## Estructura de una respuesta de health check

### Respuesta simple (200 OK)

```json
{
  "status": "Healthy"
}
```

### Respuesta detallada (RFC Draft)

```json
{
  "status": "Healthy",
  "checks": {
    "database": {
      "status": "Healthy",
      "description": "PostgreSQL connection successful"
    },
    "cache": {
      "status": "Degraded",
      "description": "Redis timeout (non-critical)"
    },
    "externalApi": {
      "status": "Unhealthy",
      "description": "Payment provider unreachable"
    }
  },
  "totalDuration": "00:00:00.1234567"
}
```

---

## Códigos de estado

| Estado | Significado | Código HTTP | Acción |
|--------|-------------|-------------|--------|
| **Healthy** | Servicio operativo | 200 OK | Continuar tráfico |
| **Degraded** | Funcional pero con problemas | 200 OK | Continuar, pero alertar |
| **Unhealthy** | No operativo | 503 Service Unavailable | Remover del servicio |

## Configuración básica

### Program.cs

```csharp
var builder = WebApplicationBuilder.CreateBuilder(args);

// Servicios
builder.Services.AddDbContext<CatalogDbContext>(options =>
    options.UseNpgsql(builder.Configuration.GetConnectionString("DefaultConnection"))
);

// Health Checks
builder.Services
    .AddHealthChecks()
    .AddNpgSql(builder.Configuration.GetConnectionString("DefaultConnection")!, name: "database")
    .AddCheck<CustomHealthCheck>("custom-check")
    .AddCheck<ApiGatewayHealthCheck>("api-gateway");

// Health Checks UI (Development only)
if (builder.Environment.IsDevelopment())
{
    builder.Services.AddHealthChecksUI().AddInMemoryStorage();
}

builder.Services.AddControllers();

var app = builder.Build();

// Endpoints
app.MapHealthChecks("/health", new Microsoft.AspNetCore.Diagnostics.HealthChecks.HealthCheckOptions
{
    Predicate = _ => true,
    ResponseWriter = UIResponseWriter.WriteHealthCheckUIResponse
});

if (app.Environment.IsDevelopment())
{
    app.MapHealthChecksUI();
}

app.MapControllers();
app.Run();
```

## Health Check personalizado

### CustomHealthCheck.cs

```csharp
namespace Catalog.API.Infrastructure.HealthChecks;

using Microsoft.Extensions.Diagnostics.HealthChecks;

public class CustomHealthCheck : IHealthCheck
{
    private readonly IProductRepository _repository;
    private readonly ILogger<CustomHealthCheck> _logger;

    public CustomHealthCheck(IProductRepository repository, ILogger<CustomHealthCheck> logger)
    {
        _repository = repository;
        _logger = logger;
    }

    public async Task<HealthCheckResult> CheckHealthAsync(
        HealthCheckContext context,
        CancellationToken cancellationToken = default)
    {
        try
        {
            _logger.LogInformation("Executing custom health check");

            // Verificar si podemos contar productos
            var count = await _repository.CountAsync(cancellationToken);

            var data = new Dictionary<string, object>
            {
                { "productCount", count },
                { "timestamp", DateTime.UtcNow }
            };

            return HealthCheckResult.Healthy("Product repository is accessible", data);
        }
        catch (Exception ex)
        {
            _logger.LogError(ex, "Custom health check failed");
            return HealthCheckResult.Unhealthy("Product repository is not accessible", ex);
        }
    }
}
```

### Registrar

```csharp
builder.Services
    .AddHealthChecks()
    .AddCheck<CustomHealthCheck>("product-repository", tags: new[] { "db" });
```

## Health Check con lógica condicional

```csharp
public class DiskSpaceHealthCheck : IHealthCheck
{
    public async Task<HealthCheckResult> CheckHealthAsync(
        HealthCheckContext context,
        CancellationToken cancellationToken = default)
    {
        try
        {
            var drive = DriveInfo.GetDrives().First();
            var availableSpace = drive.AvailableFreeSpace;
            var totalSpace = drive.TotalSize;
            var percentFree = (availableSpace / (double)totalSpace) * 100;

            var data = new Dictionary<string, object>
            {
                { "diskFreePercentage", percentFree },
                { "diskFreeGb", availableSpace / (1024.0 * 1024.0 * 1024.0) }
            };

            if (percentFree < 5)
                return HealthCheckResult.Unhealthy("Disk space critically low", data: data);

            if (percentFree < 10)
                return HealthCheckResult.Degraded("Disk space low", data: data);

            return HealthCheckResult.Healthy("Disk space healthy", data: data);
        }
        catch (Exception ex)
        {
            return HealthCheckResult.Unhealthy("Could not check disk space", ex);
        }
    }
}
```

## Liveness vs. Readiness

En Kubernetes, hay dos tipos de probes:

### Liveness Probe

Verifica si el contenedor está **vivo** (no congelado ni en deadlock).

```csharp
// Debe ser muy rápido
app.MapHealthChecks("/health/live", new HealthCheckOptions
{
    Predicate = check => check.Tags.Contains("live")
});
```

**Configuración en Kubernetes:**

```yaml
livenessProbe:
  httpGet:
    path: /health/live
    port: 8080
  initialDelaySeconds: 10
  periodSeconds: 10
  timeoutSeconds: 2
  failureThreshold: 3
```

### Readiness Probe

Verifica si el servicio está **listo** para recibir tráfico (BD lista, etc.).

```csharp
// Puede ser más lento, incluye checks de dependencias
app.MapHealthChecks("/health/ready", new HealthCheckOptions
{
    Predicate = check => check.Tags.Contains("ready")
});
```

**Configuración en Kubernetes:**

```yaml
readinessProbe:
  httpGet:
    path: /health/ready
    port: 8080
  initialDelaySeconds: 5
  periodSeconds: 5
  timeoutSeconds: 2
  failureThreshold: 3
```

## Implementación completa en Catalog.API

```csharp
// Program.cs
var builder = WebApplicationBuilder.CreateBuilder(args);

builder.Services.AddDbContext<CatalogDbContext>(options =>
    options.UseNpgsql(builder.Configuration.GetConnectionString("DefaultConnection"))
);

builder.Services.AddScoped<IProductRepository, ProductRepository>();

// Health Checks
builder.Services
    .AddHealthChecks()
    // Liveness: solo check rápido
    .AddCheck("liveness", () => HealthCheckResult.Healthy(), tags: new[] { "live" })
    // Readiness: includes todas las dependencias
    .AddNpgSql(
        builder.Configuration.GetConnectionString("DefaultConnection")!,
        name: "database",
        tags: new[] { "ready", "db" }
    )
    .AddCheck<CustomHealthCheck>("product-repository", tags: new[] { "ready", "db" });

if (builder.Environment.IsDevelopment())
{
    builder.Services.AddHealthChecksUI().AddInMemoryStorage();
}

builder.Services.AddControllers();

var app = builder.Build();

// Health endpoints
app.MapHealthChecks("/health/live", new HealthCheckOptions
{
    Predicate = check => check.Tags.Contains("live"),
    ResponseWriter = UIResponseWriter.WriteHealthCheckUIResponse
});

app.MapHealthChecks("/health/ready", new HealthCheckOptions
{
    Predicate = check => check.Tags.Contains("ready"),
    ResponseWriter = UIResponseWriter.WriteHealthCheckUIResponse
});

// UI para desarrollo
if (app.Environment.IsDevelopment())
{
    app.MapHealthChecksUI();
}

app.MapControllers();
app.Run();
```

using Xunit;

public class HealthCheckTests
{

    public async Task Liveness_ShouldAlwaysBeHealthy()
    {
        // Arrange
        var healthCheck = new LivenessHealthCheck();

        // Act
        var result = await healthCheck.CheckHealthAsync(new HealthCheckContext());

        // Assert

## Puntos clave

- **Liveness:** ¿El servicio está vivo? (rápido, simple)
- **Readiness:** ¿El servicio está listo? (incluye dependencias)
- **Códigos HTTP:** 200 para Healthy/Degraded, 503 para Unhealthy
- **Health Checks predefinidos:** PostgreSQL, Redis, HTTP
- **Personalizados:** Implementa `IHealthCheck` para lógica compleja
- **Kubernetes:** Configura livenessProbe y readinessProbe
- **Monitoreo:** Integra con Prometheus, Datadog, etc.
